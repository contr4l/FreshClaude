## 一、文件操作三件套

### Read - 读取文件

**用途**：读取文件内容，包括代码、配置、图片、PDF等

**特点**：
- 支持行号范围读取（大文件友好）
- 支持读取图片（Claude是多模态的）
- 支持读取PDF（可指定页码范围）

**语法示例**：
```
Read(file_path="/path/to/file.py")
Read(file_path="/path/to/file.py", offset=100, limit=50)  # 从第100行开始读50行
Read(file_path="/path/to/image.png")  # 读取图片
Read(file_path="/path/to/doc.pdf", pages="1-5")  # 读取PDF前5页
```

**最佳场景**：
- ✅ 查看文件内容
- ✅ 理解代码逻辑
- ✅ 分析图片/截图
- ❌ 不要用于：列出目录（用 Bash ls）

---

### Write - 创建/覆写文件

**用途**：创建新文件或完全覆写现有文件

**特点**：
- 必须提供完整文件内容
- 会覆盖现有文件（危险操作）
- 适合创建新文件

**语法示例**：
```
Write(file_path="/path/to/new_file.py", content="完整文件内容")
```

**最佳场景**：
- ✅ 创建新文件
- ✅ 完全重写小文件
- ❌ 不要用于：修改大文件的小部分（用 Edit）

---

### Edit - 精确编辑

**用途**：精确替换文件中的特定内容

**特点**：
- 只发送变更部分，节省token
- 需要先 Read 文件
- old_string 必须唯一匹配

**语法示例**：
```
Edit(
    file_path="/path/to/file.py",
    old_string="要替换的原内容",
    new_string="新内容"
)
```

**最佳场景**：
- ✅ 修改现有文件
- ✅ 小范围改动
- ✅ 重命名变量（replace_all=true）
- ❌ 不要用于：创建新文件（用 Write）

---

### 三件套决策树

```
需要操作文件？
    │
    ├─ 读取内容 ──────────────────→ Read
    │
    ├─ 创建新文件 ────────────────→ Write
    │
    └─ 修改现有文件
            │
            ├─ 小范围改动 ────────→ Edit（推荐）
            │
            └─ 完全重写 ─────────→ Write（谨慎）
```

## 二、搜索工具

### Glob - 按模式查找文件

**用途**：根据文件名模式查找文件路径

**特点**：
- 支持通配符：`*`, `**`, `?`
- 返回匹配的文件路径列表
- 按修改时间排序

**语法示例**：
```
Glob(pattern="**/*.py")           # 所有Python文件
Glob(pattern="src/**/*.ts")       # src目录下所有TS文件
Glob(pattern="*.md", path="/docs") # docs目录下的MD文件
```

**最佳场景**：
- ✅ 找特定类型的文件
- ✅ 了解项目结构
- ✅ 批量操作前的文件列表

---

### Grep - 按内容搜索

**用途**：在文件内容中搜索匹配的文本

**特点**：
- 支持正则表达式
- 可限定文件类型
- 多种输出模式

**语法示例**：
```
Grep(pattern="TODO")                    # 搜索TODO
Grep(pattern="function\\s+\\w+", type="js")  # JS文件中的函数定义
Grep(pattern="import.*React", glob="**/*.tsx", output_mode="content")
```

**输出模式**：
- `files_with_matches`：只返回文件路径（默认）
- `content`：返回匹配的行内容
- `count`：返回匹配数量

**最佳场景**：
- ✅ 查找代码中的特定内容
- ✅ 定位函数/变量的使用
- ✅ 搜索TODO/FIXME等标记

---

### Glob vs Grep 决策

```
我要找什么？
    │
    ├─ 知道文件名/类型，不知道位置 ──→ Glob
    │   "项目里有哪些测试文件？"
    │
    └─ 知道内容，不知道在哪个文件 ──→ Grep
        "哪里用到了 UserService？"
```

## 三、Bash工具

### 能做什么

```
✅ 推荐使用 Bash 的场景：
- 运行测试：pytest, npm test
- Git操作：git status, git commit
- 包管理：pip install, npm install
- 构建项目：make, npm run build
- 系统命令：ls, pwd, which
- 启动服务：npm start, python app.py
```

### 不该做什么

```
❌ 不要用 Bash 替代专用工具：
- 读文件：不要 cat/head/tail → 用 Read
- 搜文件：不要 find → 用 Glob
- 搜内容：不要 grep/rg → 用 Grep
- 写文件：不要 echo > → 用 Write
- 改文件：不要 sed/awk → 用 Edit
```

**为什么？**
- 专用工具有权限控制
- 专用工具输出更友好
- 专用工具便于审查

## 四、工具组合：并行与串行

### 并行调用

**条件**：工具调用之间没有依赖关系

**示例**：同时读取多个文件
```
┌─────────────┐  ┌─────────────┐  ┌─────────────┐
│ Read(a.py)  │  │ Read(b.py)  │  │ Read(c.py)  │
└─────────────┘  └─────────────┘  └─────────────┘
       │                │                │
       └────────────────┼────────────────┘
                        ▼
                  同时执行，节省时间
```

### 串行调用

**条件**：后续调用依赖前一个调用的结果

**示例**：先搜索再读取
```
┌─────────────────────┐
│ Grep("UserService") │  ← 第一步：找到文件
└─────────────────────┘
           │
           ▼
┌─────────────────────┐
│ Read(找到的文件)     │  ← 第二步：读取内容
└─────────────────────┘
```

### 并行+串行组合

```
              ┌─────────────┐
              │ Glob(*.py)  │  ← 第一步：找文件
              └─────────────┘
                     │
        ┌────────────┼────────────┐
        ▼            ▼            ▼
┌───────────┐ ┌───────────┐ ┌───────────┐
│ Read(1.py)│ │ Read(2.py)│ │ Read(3.py)│  ← 第二步：并行读取
└───────────┘ └───────────┘ └───────────┘
```

## 核心要点

1. **Read/Write/Edit 各有适用场景** - 修改用 Edit，创建用 Write
2. **Glob 找文件名，Grep 找内容** - 不要混淆
3. **Bash 用于系统命令** - 不要替代专用工具
4. **能并行就并行** - 提高效率
5. **有依赖就串行** - 保证正确性
